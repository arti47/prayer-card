## 1. What This Project Is

A **personal prayer journal web app** built from the **Redemption Hill Church "Practicing The Way: Prayer"** study guide (a local adaptation of John Mark Comer's *Practicing The Way* curriculum).

It combines **three rhythms** into one app:

| Practice | Source | Rhythm | What it does |
|---|---|---|---|
| **Prayer Story Cards** | Session 4 — based on Paul Miller's *A Praying Life* | Ongoing | Track prayers as long-term stories. 8–12 cards, each with a Scripture anchor, two-level "ask," and Father's Perspective line. Story notes added weekly. A **"🙏 Pray these now"** button on the Story Cards tab opens a quick 5-min walkthrough. |
| **Daily Prayer** | Tim Keller, *Prayer: Experiencing Awe and Intimacy with God*, Ch. 15 | Daily | Three plans — Morning (25 min), Evening (15 min), Starter (15 min). Each: Approach → Bible reading & meditation → Prayer → Contemplation. Scriptural invocations picker (13 passages) on the Approach step. Meditation step has Simple (3-question) and Full (6-question) modes; user toggles. Petition / Free Prayer fields include a "🃏 Pray story cards →" button. **Note:** Keller's name doesn't appear in the everyday UI per the editorial care rule in §5; it's only in the Credits block. |
| **Weekly Deep Time** | RHC's *Practicing The Way: Prayer* (Session 3 Listening Prayer + Preparing-to-Pray exercise) | Weekly (Sunday) | 7-step guided journal: Prepare (Circumstances, Feelings, Mapping the Heart) → Come → Humble → Ask → Repent → Forgive → Follow. Each prayer step has paired Pray + Listen prompts. *(Was "Pray & Listen" pre-restructure.)* |

### Audience
- **Primary:** the owner (Tai Yao) for personal weekly practice.
- **Secondary (eventual):** sharing with church + friends. Keep that in mind for design decisions — don't bake in anything personal-identifiable, keep wording reverent, never assume tech savvy.

### Source attribution
Content is adapted from **Redemption Hill Church**'s study guide. Scripture, prompts, the "Needs of the Heart" chart, and the Lord's Prayer flow are all drawn directly from that material. If we ever publish/distribute, we need explicit permission from RHC and credit to *Practicing The Way* and *A Praying Life* (Paul Miller).

## 2. Tech Stack & File Layout

**Currently:** PWA-ready single-file HTML5 app. No build step, no dependencies, no backend. localStorage for persistence. Anything beyond this (React, native iOS, real backend) is *not* on the table without a clear reason.

```
Prayer App/
├── index.html         ← the entire app (UI + logic + styles)
├── manifest.json      ← PWA manifest (name, icons, theme colors)
├── sw.js              ← service worker (network-first HTML, cache-first assets)
├── icon.svg           ← any-purpose icon (rounded square, gradient + cream sparkle)
├── icon-maskable.svg  ← maskable variant (smaller star inside safe zone)
├── README.md          ← public-facing project readme (features, privacy, credits)
├── LICENSE            ← license file
├── bible/             ← 66 markdown files, one per book (full ESV text).
│                         Powers the full-Bible Scripture-lookup fallback:
│                         lazy-fetched by index.html and precached by the SW
│                         (APP_SHELL) so lookups work offline.
└── CLAUDE.md          ← this file
```

> **Note on the Prayer Library source:** the ~40 written prayers surfaced by the
> P8 #53 Prayer Library were originally transcribed from a bundled `a way to pray/`
> folder (Matthew Henry). That folder is **no longer in the repo** — the prayer
> text now lives inline in the `PRAYER_LIBRARY` constant in `index.html`, so the
> app is self-contained. Older roadmap/changelog notes below still reference the
> old folder path as historical provenance.

### ⚠️ Hosting requirement for full PWA features
Service workers (and therefore offline support and Android install prompt) only register over **HTTPS** or **localhost** — not `file://`. The app currently lives in iCloud Drive and is opened via `file://` in Safari, which means:
- ✅ Manifest + iOS meta tags work — "Add to Home Screen" gives a proper icon and standalone display
- ❌ Service worker won't register, so true offline mode and updates-via-cache don't activate
To unlock full PWA: deploy the folder to GitHub Pages / Netlify / Vercel (free) and visit that URL. The SW registration script is gated by protocol so it silently skips on `file://` rather than erroring.

- ✅ Daily prayer mode — walk through cards using a 5-prompt Lord's Prayer flow (Come & Worship · Trust & Submission · Ask · Repent · Follow). Prompts auto-fill from card data where grammar is safe: the user's own `perspAttr`/`perspTrust` fill-ins splice into sentences; the card title and both asks render as named items (Repent uses apposition — "I release this story — *{person}* —"; Ask lists "the circumstance" / "the heart" as quiet lines). ### 🛠️ Infrastructure
- ✅ localStorage persistence (`prayer_cards`, `pl_sessions`, `pl_draft`, `streak_days`, `daily_<date>`)
- ✅ Storage failure handling — all writes go through `safeSetItem()` / `safeRemoveItem()` wrappers. Distinguishes `QuotaExceededError` (storage full) from `SecurityError` (private mode, Brave shields, etc.) and shows a specific toast for each. Toasts are rate-limited to once per 5 seconds so auto-save during a typing burst doesn't flood the user. On app start, `storageAvailable()` does a probe write/remove — if it fails, surfaces a "⚠ Your browser is blocking local storage" warning toast after 800ms.
- ✅ Toast notifications
- ✅ 5-tab bottom nav: 🃏 Story Cards · ☀️ Daily Prayer · ✍️ Weekly Deep · 🪞 Reflect · ✦ Guide. **Reflect** holds stats/analysis + settings (Your Stats, Year at a Glance, Answered Prayers, Heart Needs Over Time, What You've Been Hearing, Weekly Review, then a "Settings" divider: Appearance, Markdown Export, Backup & Restore). **Guide** is pure orientation (tour, the 3 practice explainers, Install, Credits, Privacy). `showView('reflect')` renders the analysis blocks + applies theme/text-size + populates Obsidian fields; `showView('guide')` only renders the install block.

## 5. Design Principles & Guardrails

These are non-negotiable. Don't override without explicit permission from the user.

### ✅ Aesthetic / tone
- Warm, contemplative, reverent. Serif body type (Georgia). Tan/brown palette anchored on `#7a5c3e`. Generous whitespace.
- Use the user's exact wording from the source PDFs whenever possible — don't paraphrase Scripture, prompts, or the Lord's Prayer phrasing.
- Each Pray & Listen step has its own colour identity that carries through the step header, quote pill, listen block, and history chips.

### 🚫 Never do these
- ❌ **No AI suggestions inside prayer fields.** The Listen step is for God's voice, not a model's. Don't add "AI assist" or autocomplete to prayer textareas.
- ❌ **No gamified streaks beyond the simple 7-dot row.** No XP, no achievements, no streak-shaming. Prayer ≠ Duolingo.
- ❌ **No social / share / public features.** This is a private practice. No "share to Twitter," no public profiles, no leaderboards.
- ❌ **No nag notifications / reminders.** Calendar is better. Prayer should not become another app pinging the user.
- ❌ **No emojis in code unless the user asks.** Emojis in the UI are fine where they already exist (✦, 🃏, 🙏, ✍️, 🔔, 🕊️) — those are part of the established design.
- ❌ **No tracking, analytics, or telemetry.** Ever.

### 🎯 Editorial care
- "Father" and "Lord" are capitalised. "Scripture" capitalised when referring to the Bible.
- Use em-dashes and proper smart quotes, not straight quotes, in user-facing copy.
- "Listen" sections are the heart of the practice. Never undervalue them in UI weight, never collapse them by default, never auto-skip.
- **Attribution lives in Credits, not in everyday UI copy.** The Guide tab's "📜 Credits & Source Material" block names the source authors (Redemption Hill Church, Paul Miller, Tim Keller, Matthew Henry) explicitly. Banners, instructions, step prompts, tab descriptions, and roadmap descriptions should describe the *practice itself*, not credit any specific author. This includes secondary names quoted within the sources (e.g. George Mueller's question framework cited inside Keller's chapter — call them "meditation questions" or "reflection questions," not by the originator). This keeps the everyday experience contemplative rather than academic.

### P8 — Awe / Praise (added 2026-05-23 from a Keller Ch. 12 study + Matthew Henry source)
